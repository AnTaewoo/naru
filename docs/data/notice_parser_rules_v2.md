# Naru 공지 파서 규정서 v2

작성 2026-11-07 · 대상: 통제 공지 문장을 구조화하는 파서(`NoticeParser`, Claude API) · 이 문서는 Syntitan 케이스 생성과 Claude 프롬프트 v1의 공통 기준이다.

---

## 0. 한 줄 정의

**입력**: 통제 공지 한 건(문장 또는 표의 한 행) + 출처 + 게시 시각.
**출력**: 그 공지가 말하는 **시간 구간**, **장소 이름**(점 또는 구간), **종류**, **보행 관련 여부**. 전부 공지에 적힌 표현을 정규 이름으로 바꾼 것이다. **좌표는 출력하지 않는다.** 좌표는 파서 뒤의 지명사전이 붙인다.

파서가 틀리면 틀리는 방향은 둘뿐이다: 공지에 없는 것을 지어내거나, 공지에 있는 것을 빠뜨리거나. 전자가 더 나쁘다. 모르면 `null`.

---

## 1. 입력

### 1.1 출처 A — 서울경찰청 「오늘의 주요집회」 (PDF 표)

하루 한 장. 머리에 `2026. 11. 7.(토)`(집회 날짜)와 `(2026. 11. 6. 18:00 기준 작성)`(작성 시각). 표 한 행이 공지 한 건.

| 열 | 예 | 뜻 |
|---|---|---|
| 집회 일시 | `12:00~16:00` | 당일 시작~종료. 날짜는 머리의 집회 날짜 |
| 집회 장소(행진로) | `동화면세점 앞 → 종로1R → 동화면세점 앞 <세종대로 등>` | 장소·경로. 꺾쇠 안은 도로 힌트 |
| 신고 인원 | `50,000명` | 신고 규모 |
| 관할서 | `종로, 남대문` | 경찰서. 위치 힌트로만 |
| 비고 | 보통 빈칸 | |

**표기 사전** (장소 열 안에서 쓰이는 기호)

| 기호 | 뜻 | 처리 |
|---|---|---|
| `A → B → C` | 행진. A에서 출발해 B를 거쳐 C 도착 | `segment{from A, via [B], to C, direction one_way}` |
| `A ↔ B` | 양방향 행진·왕복 | `segment{from A, to B, direction both}` |
| `A ~ B` (화살표 없음) | A부터 B까지 **늘어서는** 집회 (행진 아님) | `segment{from A, to B, kind rally_stretch}` |
| `A → B → A` | 순환 행진 | `from A, via [B], to A` 그대로. 합치지 않는다 |
| `<세종대로 등>` `<여의도>` | 도로·지역 힌트. "등"은 더 있다는 뜻 | `road_hints`에 담는다. **segment.road에 바로 넣지 않는다** (§3.4) |
| `R` | 로터리/사거리/오거리 | 지명사전이 정한다. `종로1R`→`종로1가사거리`, `숭례문R`→`숭례문오거리`, `내자R`→`내자동사거리` |
| `出` | 지하철 출구 | `서초역 8出`→`서초역 8번출구` |
| `앞`, `정문 앞`, `동측`, `남단`, `북단`, `건너편` | 장소의 어느 쪽 | 이름에 그대로 붙여 둔다. 지명사전이 쓴다 |
| `인도` | 보도 위 집회 | **보행 폐쇄 아님** → `scope: sidewalk_only` (§4) |
| `·` | 나열 | `금감원·여의도역` → 두 장소. 행진 경로 안에서는 **같은 지점의 두 이름**이 아니라 **연속 두 지점**으로 본다 |

### 1.2 출처 B — TOPIS 통제 공지 (텍스트)

예:
```
15:00∼17:00 서울시의회∼숭례문(편도全차로) ※③행진:서울시의회→한국은행→을지로1가→을지로2가→고용노동청(1.6km, 3개차로) 부분통제
발생일시 11.07 15:00
완료예정 11.07 17:00
```

| 조각 | 뜻 |
|---|---|
| `15:00∼17:00` | 시간. `발생일시`/`완료예정`가 있으면 그쪽이 우선(날짜가 있으니까) |
| `서울시의회∼숭례문` | **통제 구간** (집회 본대 자리). `kind: closure` |
| `(편도全차로)` | 차로 범위. `편도 전차로` = 한 방향 전부 |
| `※③행진: A→B→…→E` | 번호 붙은 행진 경로. 번호 = `order`. 한 공지에 ①②③ 여러 개면 **각각 별도 segment** |
| `(1.6km, 3개차로)` | 길이·차로 수 |
| `부분통제` / `전면통제` | `lanes.scope` partial / full |
| `발생일시 11.07 15:00` | MM.DD HH:MM. 연도는 게시 시각에서 |

TOPIS는 같은 집회를 행진 번호마다 한 건씩 올린다. **통제 구간(서울시의회∼숭례문)은 세 건에 다 들어 있으므로 한 번만 내고, 행진은 셋 다 낸다.** 중복 제거는 파서가 아니라 뒤 단계(BE)가 한다 — 파서는 받은 한 건만 충실히 낸다.

### 1.3 입력 봉투

파서는 항상 이걸 받는다:
```json
{
  "source": "smpa | topis",
  "text": "<표의 한 행 또는 공지 한 건, 원문 그대로>",
  "event_date": "2026-11-07",          // smpa: 머리의 날짜. topis: null (발생일시에서 읽는다)
  "published_at": "2026-11-06T18:00+09:00",
  "fetched_at": "2026-11-07T09:10+09:00"
}
```

## 2. 출력 스키마

```json
{
  "window":  { "start": "2026-11-07T15:00+09:00", "end": "2026-11-07T17:00+09:00" },
  "kind":    "march | rally_point | rally_stretch | closure | marathon | unknown",
  "scope":   "pedestrian | sidewalk_only | vehicle_only | unknown",
  "segments": [
    {
      "order": 3,                       // ※③ 같은 번호. 없으면 null
      "from":  "서울시의회",
      "to":    "고용노동청",
      "via":   ["한국은행", "을지로1가", "을지로2가"],
      "road":  null,                    // 문장이 이 구간의 도로를 말할 때만
      "direction": "one_way | both",
      "lanes": { "count": 3, "scope": "partial | full | one_side_full | null" },
      "length_km": 1.6
    }
  ],
  "points": [                           // 구간이 아닌 한 지점 집회
    { "name": "교보빌딩 정문 앞", "road_hint": "세종대로" }
  ],
  "road_hints": ["세종대로"],
  "reported_people": 50000,
  "police_stations": ["종로", "남대문"],
  "spans": [                            // 문장 안 표현 → 정규 이름. 평가용
    { "text": "종로1R", "tag": "INTERSECTION", "canonical": "종로1가사거리" },
    { "text": "12:00~16:00", "tag": "TIME", "canonical": "2026-11-07T12:00/16:00" }
  ],
  "confidence": 0.85,
  "reject_reason": null,                // scope가 pedestrian이 아닐 때 이유
  "notes": null                         // 애매했던 점 한 줄. 사람 검수용
}
```

- `segments`와 `points` 중 하나는 비어 있을 수 있다. 둘 다 비면 `kind: unknown` 또는 거절.
- 이름(`from`·`to`·`via`·`points.name`)은 **공지 표현을 정규 이름으로 바꾼 것**. 바꿀 근거가 없으면 원문 그대로 두고 `notes`에 적는다.
- **없는 필드**: 좌표, 횡단보도 ID, 주소. 파서는 이걸 모른다.

태그: `TIME` · `ROAD`(세종대로) · `INTERSECTION`(종로1가사거리) · `POI`(동화면세점, 서울시의회, 서초역 8번출구) · `ADDRESS`(도로명주소 전체) · `AREA`(여의도, 적선동).

## 3. 해석 규칙

### 3.1 시간
1. `HH:MM~HH:MM`, `∼`, `-` 전부 같은 뜻.
2. 날짜 우선순위: `발생일시/완료예정` > `event_date` > `published_at` 다음 날(공지가 "내일"이면) > `published_at` 당일.
3. 종료가 시작보다 이르면 다음 날 종료.
4. `16:05`처럼 분이 있으면 그대로. 반올림 금지.
5. "~까지", "이후", "오후 2시부터" 같은 반쪽 표현: 있는 쪽만 채우고 없는 쪽 `null`. 끝이 없으면 `window.end: null`.
6. `connector`가 "낮 12시", "오후 3시 30분"이면 24시간제로. "오전/오후"가 없고 12 이하이면 **그대로 두고 `notes`**("오전·오후 불명").

### 3.2 종류 `kind`
| 문장에 | kind |
|---|---|
| `→`, `행진`, `↔` | `march` |
| `A ~ B`(화살표 없음, 두 지점) | `rally_stretch` |
| 한 지점(`앞`, `出`, `정문`) | `rally_point` |
| `통제`, `전면통제`, `편도全차로`(행진 표시 없이) | `closure` |
| `마라톤`, `대회`, `코스`, `출발/반환` | `marathon` |
| 판단 불가 | `unknown` |
한 행에 `A~B → C`가 있으면(11/7 4행 `시의회~숭례문R → 광화문·고용노동청`): `rally_stretch{시의회→숭례문R}` 하나 + `march{숭례문R→광화문→고용노동청}` 하나. 두 개 segment, kind는 각각.

### 3.3 장소 이름 정규화
1. 약칭(`R`, `出`)은 §1.1 표대로 풀되, **최종 정규 이름은 지명사전이 정한다.** 파서는 `canonical`에 제일 그럴듯한 이름을 적고 확신이 없으면 원문 그대로.
2. `앞`·`정문 앞`·`동측`·`남단`·`북단`·`건너편`은 떼지 않는다. 지명사전이 방향 힌트로 쓴다.
3. `광화문·고용노동청` 같은 `·` 연결은 **두 지점**(`광화문`, `고용노동청`)으로 나눈다.
4. 같은 이름의 다른 장소(`고용노동청`: 서울고용노동청 vs 고용노동부)는 파서가 고르지 않는다. 원문 이름 + `notes`.

### 3.4 도로 `road`와 `road_hints`
- `<세종대로 등>`은 **행 전체의 힌트**다. `road_hints`에 넣는다.
- `segment.road`는 **문장이 "이 구간이 이 도로를 따라간다"고 명시할 때만** 채운다 (예: "태평로 일대를 따라", "서초대로를 따라"). 꺾쇠 힌트 하나에 segment가 하나뿐이면 그 segment의 road로 올려도 된다. segment가 둘 이상이면 **올리지 않는다** — 어느 구간이 그 도로인지 모르니까.
- 도로명을 **추론해서 쓰지 않는다.** "세종대로사거리→흥인지문사거리"가 종로를 지난다는 건 파서가 할 말이 아니다. `road: null`. 뒤 단계(도로 그래프)가 찾는다.

### 3.5 구간 `segments`
1. 화살표 사슬 `A→B→C→D`: `from A, to D, via [B, C]`. 순서 보존.
2. `A→B→A`: 그대로. `from A, to A, via [B]`.
3. `↔`: `direction: both`. `→`만 있으면 `one_way`. `~`(stretch)는 방향 없음 → `one_way`로 두고 `notes` 없음(의미상 무방향).
4. `(1.6km, 3개차로)`: `length_km 1.6`, `lanes.count 3`. `부분통제` → `lanes.scope partial`, `전면통제`/`全차로` → `full`, `편도全차로` → `one_side_full`.
5. `※①②③` 번호 → `order`. 같은 공지의 통제 구간(`서울시의회∼숭례문`)은 `kind closure`, `order null`.
6. 양 끝 중 하나라도 이름이 없으면 segment를 만들지 않고 `points`로 내린다. (`여의도 일대 → ?` 같은 것)

### 3.6 지점 `points`
- `rally_point`는 `points` 하나. `road_hint`는 꺾쇠 힌트.
- `A ~ B`에서 A·B가 지역명(`여의도`, `적선동`)이면 segment가 아니라 **AREA 지점**. `kind rally_stretch` 유지, `segments []`, `points [{name: 여의도, tag AREA}]`, `notes: "지역명만"`.

### 3.7 인원·관할서
- `50,000명` → `50000`. 없으면 `null`.
- 관할서는 그대로 배열. 위치 추정에 쓰지 않는다 (파서가 아니라 검수자가 본다).

### 3.8 확신도 `confidence`
규칙으로 정한다. 모델이 느낌으로 적지 않는다.

| 조건 | confidence |
|---|---|
| TOPIS 통제 공지, 시간·구간·차로 전부 있음 | 0.90 |
| 경찰청 행진(`→`/`↔`) + 도로 힌트 있음 | 0.85 |
| 경찰청 행진, 도로 힌트 없음 | 0.75 |
| `rally_stretch` 두 지점 있음 | 0.75 |
| `rally_point`, 인원 ≥ 1,000 | 0.65 |
| `rally_point`, 인원 < 1,000 | 0.45 |
| 지역명만 (`AREA`) | 0.40 |
| 시간이 반쪽(`end null`) | 위에서 −0.15 |
| 장소 정규화 실패해 원문 그대로 둔 이름이 있음 | 위에서 −0.10 |
| `scope`가 `pedestrian`이 아님 | 0.00 (후보 아님) |

뒤 단계는 0.7 미만이면 사람 검토 큐로 보낸다. 그러니 애매하면 **낮게**.

## 4. 거절·보류 (`scope`)

파서의 목적은 **횡단보도가 막히는가**를 뒤 단계가 판단할 재료를 주는 것이다. 다음은 재료가 아니다.

| 문장에 | scope | reject_reason | 출력 |
|---|---|---|---|
| `인도` (보도 위 집회) | `sidewalk_only` | `"보도 위 집회, 차도 점유 없음"` | points는 채우되 segments 비움. 뒤 단계가 구역 표시만 |
| `가변차로 운영`, `차로 축소`, `우회 운행 권장`만 있고 행진·점유 표현 없음 | `vehicle_only` | `"차량 조치만"` | segments 비움 |
| `통제 해제`, `종료`, `정상 소통` | `vehicle_only` | `"해제 안내"` | window만 채우고 나머지 비움. 뒤 단계가 released 처리 |
| 교통경찰 배치, 안전문자 발송, 앱 안내 등 **조치 설명** | `unknown` | `"통제 정보 없음"` | 전부 비움 |
| 날짜·시간이 전혀 없음 | 원래 scope | — | `window null`, confidence 0.40 이하, `notes` |

`scope: pedestrian`은 **차도 위에 사람이 있거나 차도가 막힌다**는 표현이 있을 때: 행진, `~` 구간 집회, `통제`, `全차로`, `N개차로`, 마라톤.

**거절은 후보를 안 내는 것이지 문장을 버리는 것이 아니다.** `window`·`points`·`spans`는 가능한 만큼 채운다.

---

## 5. 금지

1. **좌표·주소·횡단보도 ID를 쓰지 않는다.** 스키마에 칸이 없다.
2. **문장에 없는 도로명·지점을 넣지 않는다.** 경로가 "분명히" 세종대로를 지나도 안 적혀 있으면 `null`.
3. **두 건을 합치지 않는다.** 같은 집회가 세 행이면 세 번 낸다.
4. **시간을 넓히거나 좁히지 않는다.** "15:00~17:00"을 "14:30~17:30"으로 여유 주지 않는다.
5. **인원으로 거절하지 않는다.** 100명이어도 후보는 낸다. 확신도만 낮춘다.
6. `notes`에 추측을 쓰되 **출력 필드에는 넣지 않는다.**

## 6. 예시 (실제 공지 그대로)

### 6.1 경찰청 11/7 1행 — 순환 행진
입력 `12:00~16:00 | 동화면세점 앞 → 종로1R → 동화면세점 앞 <세종대로 등> | 50,000명 | 종로, 남대문`
```json
{"window":{"start":"2026-11-07T12:00+09:00","end":"2026-11-07T16:00+09:00"},
 "kind":"march","scope":"pedestrian",
```

## 7. Syntitan 케이스 생성 지침

이 규정서와 원문(경찰청 PDF 11/7·11/8·11/9, TOPIS 공지)을 올려 케이스를 뽑는다. 케이스 하나 = `입력 봉투(§1.3)` + `기대 출력(§2)` + `유형`.

**유형과 수 (총 30)**
| 유형 | 수 | 뽑는 곳 |
|---|---|---|
| 정상 — 행진 `→` | 8 | 경찰청 11/7 1·2·4행, 11/9 1·2행, TOPIS ①②③ |
| 정상 — 늘어선 집회 `~` | 3 | 11/7 3·5행, TOPIS 통제 구간 |
| 정상 — 지점 | 4 | 11/8 3행, 11/9 3·4행 |
| 놓치기 쉬운 — 순환·양방향·혼합(`~`+`→`) | 4 | 11/7 1·2·4행 변형 |
| 놓치기 쉬운 — 약칭·`·`·방향어 | 4 | `종로1R`, `8出`, `금감원·여의도역`, `사랑채 동측 건너편` |
| 놓치기 쉬운 — 시간 반쪽·분 단위·날짜 없음 | 2 | `16:05~17:00`, 발생일시만 있는 TOPIS |
| 거절 — 보도 | 2 | 11/8 2행, 11/9 3행(`인도`) |
| 거절 — 차량 조치·해제·조치 설명 | 3 | 기사 문장, "통제 해제", "교통경찰 186명 배치" |

**케이스에 넣지 않는 것**: 실제 공지에 없는 지어낸 문장. 변형은 **같은 행의 표기를 바꾸는 것**(`→`를 `↔`로, 시간에 분 붙이기)까지만.

**통과 기준** (케이스마다 전부 맞아야 통과)
1. `window.start/end` 분 단위 일치
2. `kind`, `scope` 일치
3. `segments`: 개수 일치, 각 `from`·`to`·`via` **순서 포함** 일치 (정규 이름 또는 원문 — 둘 중 하나면 인정), `direction` 일치
4. `points.name` 집합 일치
5. `road`: 기대가 `null`인데 값을 넣었으면 **실패** (지어냄). 기대가 값인데 `null`이면 실패
6. `reject_reason`: 거절 케이스에서 비어 있으면 실패
`confidence`·`spans`·`notes`는 통과 기준에 안 넣는다 (부분 점수용).

## 9. v2 변경 (2026-11-07, Syntitan 148건 검토 후 태우 결정)

v1의 `scope`·`reject_reason`은 이름이 헷갈려서(`sidewalk_only`가 "사람만 다닌다"로 읽힘) 바꾼다. **출력은 한 입력에 여러 건이 있을 수 있으므로 `items` 배열**이다.

### 9.1 출력 스키마 변경
```json
{ "items": [ {
    "window": {"start": "...", "end": "..."}, "approx": false,
    "kind": "march | rally_point | rally_stretch | closure | marathon | unknown",
    "impact": "blocks | none | unknown",
    "impact_reason": null | "motorway | car_free | sidewalk | vehicle_measure | released | info_only | unconfirmed",
    "segments": [...], "points": [...], "toward": null | "을지로입구역",
    "road_hints": [], "reported_people": null, "police_stations": [], "spans": [], "confidence": 0.0, "notes": null
} ] }
```
- `impact` = 이 건이 **횡단보도 통행을 막는 재료인가**. `blocks` 차도 점유·통제 있음 / `none` 사람 통행과 무관 / `unknown` 문장만으론 모름.
- `impact_reason` = `none`일 때 왜. `motorway` 자동차전용도로·터널·램프·고가·IC / `car_free` 차 없는 거리(차만 막고 사람은 다님) / `sidewalk` 보도·광장 집회, '차도 점유 없음' 메모 / `vehicle_measure` 가변차로·우회·버스 조치만 / `released` 해제·종료·해산 / `info_only` 경찰 배치·안내·사후 서술 / `unconfirmed` "통제될 수 있다"·"검토 중".
- v1 대응: `pedestrian`→`blocks`, `vehicle_only`·`sidewalk_only`→`none`+reason.

### 9.2 규칙 추가·변경
1. **자동차전용도로는 `none/motorway`.** 올림픽대로·강변북로·동부간선도로·내부순환로·터널·램프·고가·IC 구간. 횡단보도가 없다.
2. **보행로 폐쇄·보도 공사는 `blocks`.** `kind closure`, `lanes null`. (보도 집회와 반대 — 보도 자체가 막힘)
3. **차 없는 거리·차 없는 다리는 `none/car_free`.** 차만 막고 사람은 다닌다. 덕수궁길·잠수교·청계천 보행자 전용 행사 전부. 1번과 결과(`none`)는 같지만 이유가 다르다.
4. **종료 지점 없는 행진**: segment를 만들지 않는다. 출발지를 `points`에, 문장에 있는 방향 표현(`을지로입구역 방향`)을 `toward`에 **문장에 있는 이름 그대로** 넣는다. 임의 거리로 끝점을 만들지 않는다 — 뒤 단계가 `toward`가 지명사전에 있으면 출발지→toward 선을 낮은 확신으로 긋고, 없으면 출발지 주변 구역으로 처리한다. −0.15.
5. **한 입력에 여러 건**(두 행, 두 공지가 붙어 옴, 한 행에 두 일정, 집회 후 행진): `items`에 **전부** 낸다. 합치지 않고 나란히. 각 item은 자기 window·kind.
6. **한 행에 지점 둘** ("A 및 B 각각", "A와 B 동시", "A 또는 B"): `points` 둘. segment 아님. 행진 출발지가 "또는"이면 둘 다 points + `toward`.
7. **집회 시간과 통제 시간이 둘 다 있으면 window = 둘의 합집합**(이른 시작, 늦은 끝). 확정은 뒤 단계(TOPIS 돌발·버스)가 한다.
8. **"14시경"·"오후"·"오전 중"·"약 두 시간"**: 근사값으로 채우고 **양끝 10분씩 넓힌다**, `approx: true`. `14시경 ~2시간` → 13:50~16:10. "오후"=12:00, "오전 중"=09:00~12:00, "저녁"=18:00. −0.10.
9. OCR 오타(`13:OO`): 보정하고 −0.10. 그대로.
10. **TOPIS인데 차로 정보가 없으면 0.80** (전부 있으면 0.90). 예: `청계천로 청계광장~삼일교, 야간 행사에 따른 부분 통제`(차로 수 없음) 0.80 / `올림픽로 잠실역사거리~종합운동장사거리, 마라톤 행사로 통제`(차로·범위 없음) 0.80 / `세종대로 (시청역 → 숭례문) 전차로 통제 전면통제` 0.90.
11. `sidewalk_only` 폐기 → `none/sidewalk`. 뜻은 "집회가 보도·광장에 있어 차도 통행에 영향 없음".
12. **점유 표현이 없는 지점 집회는 `impact: unknown`, 거절 아님.** `points`는 반드시 채운다. 뒤 단계가 지점이 도로 30m 안이거나 지점들이 도로를 감싸면 막는 것으로 본다 (BE 규칙, ADR 필요). confidence 0.45.
13. 시작=종료 시각: 그대로 두고 `approx true`, −0.15. 넓히지 않는다.
14. 게시 시각이 통제 시작 이후여도 그대로 낸다. released 판단은 뒤 단계.

### 9.3 평가 통과 기준 변경
- `impact` 일치 (v1의 scope 대신). `impact_reason`은 `none`일 때만 비교.
- `items` 개수 일치. item 짝은 window 시작 시각으로 맞춘다.
- `toward`: 기대가 값이면 값 일치, 기대가 null인데 값이 있으면 실패(지어냄).
- `approx` 케이스는 window ±10분 허용.
