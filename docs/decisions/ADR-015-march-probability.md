# ADR-015 행진 확률 모델 — 시간에 따라 움직이는 막힘 확률·예상 위치 키프레임
- 상태: **승인** (2026-11-10, 태우 "다음" — 돌발이 붙어 통제 중이 된 행진도 방향을 아는 사건이면 경로 전체 대신 P. 나머지 열린 질문은
  "알아서" — 아래 "정한 것"). 교수님 멘토링 피드백 T-B, 구현 T7.16
- 개정 대상: INTERFACE v0.15(§3.1 보충 — 키프레임 엔드포인트, §5 행진 예정 비용), ARCHITECTURE(BE Model `MarchModel`, 흐름),
  DB Alembic 0007(closure_events 에 행진 칸), BE config(아래 가정값), FE 지도 레이어(heatmap·원·횡단보도 P)
- 구현 Task: T7.16 (ROADMAP P7, 멘토링 블록)

## 맥락
- 지금은 행진 경로 전체를 통제 시간 내내 같은 상태로 본다. 사건(reason·창)의 모든 횡단보도가 같은 창을 갖고, 라우터는 창 안이면
  예정 횡단보도마다 +300초(`scheduled_penalty_s × walk_speed_mps` = 360 m)를 더한다(ADR-011 A). 행렬은 한 곳에 머물지 않는데
  출발점과 끝점이 처음부터 끝까지 똑같이 막힌 것으로 나온다.
- 행진이 오는 모양(실제 기록):
  - 공지 파서 항목: window{start,end} · kind march · segments[{order(늘 null — 목록 순), from, to, via[], road, direction,
    lanes{count, scope}, length_km(null)}] · points · reported_people · confidence. AI 는 구간마다 후보 `…-i{i}-seg{k}`
    (SegmentGeom from·via·to)를 만들고, BE 는 접수 때 도로 그래프 최단경로 → 등급 버퍼 → 횡단보도로 바꾼 뒤 **선은 버린다**.
  - cases_v1 K-016(11/7 경찰청 r04 "시의회~숭례문R → 광화문·고용노동청", 15:00~16:00): 라벨은 구간 2개, 실제 파싱(K-016 기록)은
    구간 1개(시의회→숭례문오거리) + 지점 2개, 인원 없음. 같은 공지를 PDF 로 읽으면 구간 3개가 숭례문오거리에서 갈라지고 인원 50,000.
  - 11/9 하나증권(PDF): 구간 1개(하나증권 앞→여의도역 via 금감원), 200명, 10:30~13:00.
  - TOPIS 통제지도 행진(11/9 국회대로 1109233, 11:00~15:30): 통제 도로 링크를 (축, linkSeq)·노드 이름으로 이은 순서 있는 LineGeom.

## 결정 (안)
A. **대상** — 다음을 모두 갖춘 행진만. 하나라도 없으면 지금 방식(창 안 고정 비용)과 정지 표시 그대로.
- type march, window start·end 둘 다.
- 순서 있는 경로: (a) 공지 구간 seg1..segN(후보 id 의 k 순)이 이어진다 — 앞 구간 끝과 다음 구간 시작이 `march_join_m` 안. 갈라지면(r04 PDF)
  대상 아님. (b) TOPIS 통제지도는 사슬이 하나인 LineGeom.
- 같은 사건의 지점(points) 후보는 기존 방식 그대로. 집회(제자리)·마라톤·전면 통제는 범위 밖.

B. **경로와 s** — 접수 때 이미 구하는 최단경로 선(EPSG:5179)을 버리지 않는다.
- 사건 행(closure_events, 0007)에 JSON 칸 하나 `march`: {path(EPSG:4326 좌표, 순서대로), length_m, queue_m, s(횡단보도 id → 경로를 따라 잰
  m — 횡단보도 점을 선에 사영)}. 대상이 아니면 null. 표를 새로 만들지 않는다(사건 id 가 열쇠, 문서형이라 JSON — CONVENTIONS §4.4).

C. **모델** — 속도는 공지에서만: v = L / (끝 − 시작). 근거 없는 기본 속도는 없다.
- 표본: v_i = v·(1 + w·u_i), u_i 는 [−1, 1] 등간격 K개(K = `march_samples`, w = `march_speed_spread`). 난수 없음 — 같은 입력 같은 출력.
- 머리 x_i(t) = v_i·(t − 시작), 꼬리 = x_i(t) − L_q. 위치 s 의 횡단보도는 `s − d_lead ≤ x_i(t) < s + L_q` 면 표본 i 에서 막힘
  (머리가 s 보다 선행 통제 거리만큼 앞에 왔고, 꼬리는 아직 s 를 안 지났다). P(t, s) = 막힌 표본 수 / K.
- 덜 막음 방지: 공지 창 [시작, 끝] 안이면 경로 위 횡단보도는 P ≥ `march_p_floor`(행진이 늦어도 열림으로 보지 않는다), 통제 중(confirmed) 행진이면 P ≥ `march_p_floor_confirmed`. 창 밖은 0.
- 함수 하나: BE Model `MarchModel.p_at(event, crosswalk_id, t)` — 라우터와 키프레임 API 가 같은 함수를 쓴다.

D. **행렬 길이 L_q** — 공지에 인원이 있으면 L_q = clamp(인원 / (폭 × `march_density`), `march_queue_min_m`, L). 폭 = 구간 lanes.count ×
   `lane_width_m`(있을 때), 없으면 도로 등급별 `march_width_m`. 인원이 없으면 `march_queue_m`.

E. **라우터**(§5 보충) — 대상 행진(A)이면 상태가 scheduled 든 confirmed 든(돌발이 붙어 통제 중이 됐어도 — 태우 11/10) 경로 전체를 같은
   상태로 보지 않는다: 비용 = P × 360 m(지금 예정 비용), P ≥ `march_p_block` 이면 간선 제외. avoided 는 지금 규칙(제외됐거나 비용이 붙은 곳).
   방향을 모르는 사건(대상 아님)·다른 유형은 그대로. 원 반경은 쓰지 않는다 — 경로 위 P 만.

F. **키프레임 API**(새, 공개) — `GET /closures/events/{id}/march?from=&to=` → 통제 시간 동안 60초마다
   {t, samples(표본별 머리~꼬리 구간을 경로 위 `march_point_step_m` 간격으로 찍은 [lng, lat]), center([lng, lat] = 그 점들의 가운데),
   radius_m(그 점들이 퍼진 반경 — 표시용), crosswalks({id: P})}. 키프레임당 점 `march_points_max` 상한. 대상이 아니면 404 not_modeled.
   ClosureEvent 스키마는 그대로(FE 는 type march 일 때만 부르고 404 면 정지 표시).

G. **화면** — heatmap(표본이 겹칠수록 진하게, 6단계), 예상 위치 원(테두리 + 채움, 시간이 갈수록 커짐 — 11/11 태우 "재생이 아니라 슬라이더 시각의 군집이 크게": 최소 반경 250 m·화면 최소 26 px, 채움 0.22·테두리 3 px·중심 글로우, heatmap 반경 14~40 px), 경로 위 횡단보도 P 6단계 색, 두 키프레임
   사이 보간(지금 또는 데모 시각), 재생 버튼(통제 시간 전체를 짧게, 배속 — 11/11 태우 "서비스상 의미 없음"으로 뺌. 시각은 슬라이더로, 카드를 열어도 슬라이더가 보인다), 카드에 "이 시각 막혀 있을 확률". 문구 "공지 일정 기준 예상 위치"
   — 실제 추적처럼 보이는 말은 쓰지 않는다(ko.ts 톤).

## 대안
- 경로 전체를 시간 내내 같은 상태(지금) — 출발점·끝점이 끝까지 똑같이 막혀 원래 길로 갈 수 있는 사람까지 돌려 보낸다.
- 기본 행진 속도(예: 3 km/h)를 넣는 방식 — 공지에 근거가 없는 값이라 쓰지 않는다(태우 지시).
- 원 반경으로 막힘 판단 — 경로 밖까지 막는다. 원은 표시용, 판단은 경로 위 P 만.
- 난수 표본 — 같은 입력이 다른 경로를 낼 수 있어 테스트·재현이 안 된다.

## 정한 것 (태우 11/10)
1. 돌발이 붙어 통제 중(confirmed)이 된 행진(11/9 국회대로 12:00)도 방향을 아는 사건이면 P 를 쓴다(E) — 태우.
2. 카드의 "이 시각 막혀 있을 확률" — 누른 횡단보도가 있으면 그 횡단보도의 P, 없으면 경로 위 가장 높은 P — "알아서".
3. 가정값 — 위 표 그대로 시작하고 11/14 현장 검증(T7.15 비교 스크립트) 뒤 고친다 — "알아서".

## 결과
- 행진 앞뒤는 일찍 열리고(덜 돌아감), 공지 창 안에서는 하한 때문에 열림으로 떨어지지 않는다.
- 접수 때 경로 선·s 를 저장한다(사건 행 JSON 하나, 0007) — 행진 사건마다 수 KB.
- 라우터는 행진 횡단보도마다 K개 표본을 본다 — /route p50/p95 를 T6.9 방식으로 전후 비교한다.
- 키프레임 응답은 통제 시간 × 1분 × 점 상한 — 4.5 시간 행진이면 270 키프레임, gzip 크기를 재서 보고한다.
4. 11/10 구현 뒤 — 속도 폭 ±50% → ±20%, 통제 중 행진 하한 0.5 추가(위 표) — 태우 "③ + ① 로 가고".
