# 11/9 통제일 버스 기록 평가 — ADR-013 보류의 근거

- 날짜: 2026-11-09(월). 다시 만들기: `uv run python scripts/eval_bus_20261109.py` — 테스트 DB(naru_test)에 실제 앱을 띄우고 기록만 싣는다(운영 DB·`data/raw`·`data/recorded` 는 읽기만).
- 결론: 1개 차로 행진 셋(국회대로·강남대로·하나증권) **시간 안에 버스가 통제 구간을 경로대로 124회** 지나갔다(하나증권 통제가 끝난 뒤 40회를 더하면 164회). 무정차 0 — 정류소 순번이 끊긴 통과가 없고, 164회 중 137회에 정차가 찍혔다. 경로 60 m 이탈 0(관측 9,429건, 최대 32.7 m). 버스는 차로 상태를 보는 신호라 부분 차로 행진에서는 횡단보도 막힘을 알 수 없다 → 버스 확신도 보정은 뺐다(ADR-013 보류, 태우 2026-11-09).
- 정정: 처음 보고(11/9 16:07)의 "152회"는 합계 실수다. 표의 통과 수를 더하면 164회, 그중 통제 시간 안이 124회다.

- 통과 = 한 차량이 구간(통제 횡단보도 30 m 안 노선 범위 ± 50 m) 앞 관측에서 20분 안에 구간 뒤 관측으로 간 것. 창 안·뒤 = 그 첫 관측이 통제 창 안인지 뒤인지. 속도 = 두 관측 사이 노선 위 평균(정차 포함). 노선 위 위치 = 정류소 순번(`sectOrd`)의 노선 위 거리 + `sectDist`.
- 정류소 순번이 끊긴(관측 사이 노선 위 60 km/h 넘게 뛴) 통과 0 — 가장 빠른 관측 사이도 55.5 km/h(국회대로 가는 길).
- 하나증권은 통제 중과 끝난 뒤 속도가 한쪽으로 기울지 않는다 — 다섯 구간 중 둘은 통제 중이 빠르고(18.4·17.3, 20.1·13.4) 둘은 느리다(14.9·18.0, 4.8·8.8). 표본은 구간마다 3~17회, 속도에 정차가 들어 있다.
- 국회대로·강남대로는 폴링이 통제 안에서만 돌아 견줄 "뒤"가 없다.

## 3. 판정할 수 없던 것
- ADR-013 의 "정상 통과(평소 1.3배 이내)"·"느림(평소 2배 초과)": "평소" = 그날 통제 시작 전 1시간인데, 2순위는 돌발이 뜬 뒤(11:04·14:00)부터, 1순위는 워커 재시작(12:05) 뒤부터라 시작 전 기록이 없다.
- 무정차: 60~120초 간격이라 정류소에 서는 순간을 다 보지 못한다. 정차가 안 찍힌 27회도 정류소 순번은 이어졌다.

## 4. 결론 — ADR-013 보류 (태우 2026-11-09)
- 1개 차로 행진(국회대로·강남대로·하나증권)에서 버스는 통제 시간 안에 124회 경로대로 지나갔다. 무정차 0건, 정류소 순번 끊김 없음.
- 버스는 차로 상태를 보는 신호라 부분 차로 행진에서는 횡단보도 막힘을 알 수 없다.
- 의미 있는 경우는 전면 통제·마라톤뿐인데, 마라톤은 시간표, 전면 통제는 대개 TOPIS 돌발이 이미 근거다.
- 11/21 전에 전면 통제를 실측으로 검증할 기회가 없어서, 검증 안 된 보정값을 경로에 넣지 않는다.
- 남긴 것: 버스 폴러는 전면 통제(공지 `lanes.scope` full·one_side_full)·마라톤만 **기록**한다(`NARU_BUS_RECORD_ONLY=1`). 노선 경로 부품 `naru_be.models.domain.bus_route.RoutePath` 와 이 스크립트 — 2027년 3월 서울마라톤에서 정류소 건너뜀으로 구간별 실제 통제·해제 시각을 확인할 때 쓴다.
