# ADR-R01 판정 규칙 — "로컬이 API만큼 한다"를 무슨 숫자로 말하나

상태: **제안** — PC-4(test 공개 전)까지 태우 승인. 승인 뒤엔 바꾸지 않는다. 바꾸면 그 판정은 사후 판정이다.

## 맥락
test를 본 뒤에 기준을 정하면, 기준이 결과에 맞춰진다. 그래서 숫자를 보기 전에 정한다.
"비슷하다"는 말로는 판정이 안 된다. 차이의 신뢰구간이 미리 정한 허용폭 안에 있는지로 판정한다(비열등성 판정).

## 결정 (제안)
1. **주지표**: test Norm-F1 (micro). 보조: Span-F1, E2E Jaccard, test_ood Norm-F1, official 슬라이스 Norm-F1
2. **비교쌍**
   - 로컬 대표: exp002 · exp003 · exp005 중 **val** Norm-F1이 가장 높은 것 (변형 포함, val로 고른다)
   - API 대표: exp004 `claude-haiku-5-5`의 두 변형(`spans_ours`, `llm_canonical`) 중 **val**에서 높은 것 — Naru가 실제로 쓸 후보가 이것이라서
   - 참고 상한: exp004 `claude-sonnet-5-5` — 판정에는 쓰지 않고 거리만 보고
3. **Δ = 로컬 − API**, 기사 단위 paired 부트스트랩 95% CI (`docs/experiments.md` §3.5)
4. **허용폭 δ = 0.05** (제안)
   - CI 하한 > 0 → **우세**
   - CI 하한 > −δ → **동급** (비열등)
   - CI 상한 < −δ → **열등**
   - 그 밖 → **판정 불가** (표본 부족 — test를 늘려 재측정은 v1)
   - δ 근거: Norm-F1 0.05 차이는 대략 (태그, 정규형) 100개 중 5개를 더 틀리는 정도다. 문장당 4~5개라면 4~5문장에 하나꼴. Naru에선 확신이 낮은 후보가 수동 검토 큐로 가므로 감당할 수 있다고 본다 — **태우가 수용 여부를 정한다**
   - δ를 test 표본으로 가를 수 있어야 의미가 있다. PC-4에서 val의 paired CI 폭을 보고, 폭이 δ보다 넓으면 test를 늘리거나 δ를 다시 본다 (test를 보기 전에)
5. **선택은 val로만.** 로컬 대표·API 대표·변형 선택은 전부 val. test는 선택이 끝난 뒤 1회
6. test와 test_ood의 판정이 다르면 둘 다 쓰고, 주판정은 test
7. **IAA보다 높은 시스템 점수는 의심한다.** 보고서에 따로 쓴다

## 판정이 Naru에 주는 것
| 판정 | Naru |
|---|---|
| 우세·동급 | 로컬 + 사후학습을 기본으로 → ADR-007. Naru P5에 학습·서빙 파이프라인 Task, API는 교사·감사용 |
| 열등 | API를 기본으로. 로컬은 v1(관계 라벨·교사 라벨 ADR-R03·라벨 증량) 뒤 재측정 |
| 판정 불가 | 라벨 증량 먼저. 학습량 곡선 기울기로 필요량 추정 |

어느 판정이든 "관계(행진 경로 조합)는 미측정"을 같이 쓴다.
