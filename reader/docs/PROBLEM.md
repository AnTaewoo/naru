# PROBLEM.md — 과제 정의 v0

## 1. 왜 이 과제인가
Naru는 통제 공지(마라톤·집회 행진)를 보행 그래프의 폐쇄로 바꿔야 한다. 공지는 자유 텍스트다. 조사 때 본 실제 표현:
- "세종대로 일대(숭례문∼시청교차로)" · "세종R·태평R·숭례문R" · "서울역~숙대입구~삼각지역R 구간을 반대 방향 2개 차로를 이용해"

여기서 **언제(TIME)** 와 **어디(ROAD·INTERSECTION·POI·ADDRESS)** 를 뽑아 **정규형**으로 바꾸고, 정규형을 **사전(리졸버)** 으로 좌표·횡단보도에 붙인다.
**좌표는 모델이 만들지 않는다.** 모델이 위경도를 생성하면 그럴듯하게 틀린 좌표가 나온다. 모델은 이름을 고르고, 좌표는 사전에서 찾는다.

## 2. 파이프라인
```
문장 ─[추출]→ 스팬(tag, start, end) ─[정규화]→ canonical ─[해석]→ 좌표 · 횡단보도 ID
        ↑ 실험 대상          ↑ 공용 정규화기(R4.1)          ↑ 공용 리졸버(R2.4)
        exp001–005             또는 모델이 직접(exp004·005 변형)
```
정답과 예측에 **같은 리졸버**를 쓴다. 리졸버 오류는 양쪽에 똑같이 들어가 상쇄되고, 지표 차이는 모델 차이만 남는다.

## 3. 입력 — 주석자가 보는 것 = 모델이 보는 것

| 필드 | 설명 |
|---|---|
| `text` | 라벨 대상 문장 (NFC) |
| `context_prev`, `context_next` | 앞뒤 1문장. 라벨하지 않는다. 날짜·장소 단서용 |
| `published_at` | 게시 시각 KST. "내일", "오후 2시" 같은 상대 시간의 기준 |
| `source_type` | `news` · `topis` · `smpa` · `seoul_press` |

주석자가 기사 원문을 찾아 읽고 라벨하면, 모델이 볼 수 없는 정보로 정답을 만든 셈이다. 그래서 금지한다.

## 4. 태그 (v0, 5종)

| 태그 | 무엇 | 정규형 | 정규형 기준 |
|---|---|---|---|
| `TIME` | 통제·행사·행진의 시각이나 기간 | ISO 8601 구간 `시작/끝`, 모르는 쪽은 `..`, `+09:00` | `published_at` + 문맥 |
| `ROAD` | 도로 이름 | 공식 도로명 | 도로명 사전 (R2.2) |
| `INTERSECTION` | 교차로 (약칭 `R`, 사거리·삼거리 포함) | 사전의 교차로명 그대로 | 교차로 사전 (R2.1) |
| `POI` | 지점이 되는 장소: 건물·광장·문·역·다리·공원 | 대표 명칭 | 카카오 장소 검색 기록 (R2.3) |
| `ADDRESS` | 번지가 있는 주소 | 전체 도로명주소 | 카카오 주소 검색 기록 (R2.3) |

- 사전에 없는 ROAD·INTERSECTION: 정규형 `NOGAZ:<표면형>`. E2E에서 빠지고 Norm-F1에선 문자열로 비교한다. 많이 나오면 사전 구멍이다 (PC-3에서 본다).
- 경계·조사·중첩 규칙은 `docs/labeling_guide.md`.

## 5. 출력 형식
`experiments/<exp_id>/predictions_<split>.jsonl` 한 줄:
```json
{"sentence_id": "…", "system": "exp002", "variant": "base", "seed": 13,
 "spans": [{"start": 0, "end": 4, "tag": "ROAD", "text": "세종대로", "canonical": "세종대로"}],
 "latency_ms": 12.3, "usage": null}
```
`text[start:end] == spans[i].text`가 항상 참이어야 한다. LLM처럼 오프셋 없이 텍스트만 내는 시스템은 정렬기(R4.5)가 위치를 찾는다. 못 찾은 스팬은 헛것(spurious)이다.

## 6. 지표 (정의는 `docs/experiments.md` §3)

| 지표 | 보는 것 | 비고 |
|---|---|---|
| **Norm-F1** (주지표 제안 — ADR-R01) | 문장별 (tag, canonical) 집합 | 경계가 달라도 정규형이 맞으면 정답. Naru가 실제로 쓰는 것 |
| Span-F1 strict | (tag, start, end) 집합 | 추출 능력 자체 |
| E2E Jaccard v0 | INTERSECTION·POI·ADDRESS → 반경 30m 횡단보도 집합 | 점 기반. ROAD는 v0 E2E에서 뺀다 |
| 점 P/R@15m | 정답 지점 근처에 예측 지점이 있나 | 이웃 교차로를 고른 오답을 부분 인정 |
| 비용·지연 | 1,000문장당 USD, 문장당 p50/p95 ms | 로컬은 같은 GPU에서 실측 |

## 7. v0에서 하지 않는 것 (v1 후보)
- **관계**: 구간 FROM→TO, 시간↔장소 짝, 행진 순서. **API가 앞설 것으로 예상되는 곳이다.** v0 결과가 "로컬 동급"이어도 행진 경로 조합 능력은 아직 측정 안 된 상태다. 보고서에 반드시 쓴다.
- **SCOPE**: 차로·방향 범위 ("반대 방향 2개 차로", "모든 차로")
- 지역명 (여의도, 도심 일대) — v1 `ZONE` 태그 후보 (Naru `zone_scheduled`와 연결)
- 문장이 통제를 말하는지 분류 — v0에선 수집 필터가 대신한다
- ROAD 구간 → 횡단보도 (E2E v1: 도로 + FROM/TO → 그래프 경로)
- 현장 정확도 (예측한 통제 vs 광화문 현장 관측) — Naru 현장 데이터(`data/raw/field/`)와 연결
